## Checkpoint 2 — update, state and model ordering

Main frame 0x45f070 -> 0x44f650 is a recursive object-hierarchy walk. Tiny thunk
0x45069c dispatches object virtual +8; this is 0x602b70 on the selected actor and
0x5e37f0 on its model component. The parent updates before child traversal;
frame context at game +0x4148 carries a parent matrix pointer and timestep +4.
The walk swaps the matrix pointer to object +0x50 while visiting object +0x40
children, then restores it. Base constructor 0x473870 registers objects in the
root list before child construction reparents them.

Actor update reaches 0x65a570 -> 0x568930: embedded state dispatcher at actor
+0xf8 invokes 0x568960. It updates current state, processes queued messages and
applies pending transitions. Transform composition follows. Model update advances
motion (0x56b850), calls model +0x28/+0x2c, reaches shared pose evaluator via
0x5e5220, then two guarded motion-event/channel consumers through 0x5f9b10 -> 0x6ad170.
Weapon attachment virtual +8 is 0x56b610, reading a bone transform from owner
model +0x110 through 0x56ab10. Exact branch gates and numeric formats still tracked.

The later event-signaled workers have original labels “hide manager” and
“calcmanager Trace”; “boid manager” is serviced synchronously at this callsite.
Their event signals alone do not establish completion before the next frame.
Do not classify them as the skeletal animation scheduler.

Alternate spawn 0x4466a0 stores records in 256 slots, stride 0x170. Consumer
0x445580 reaches 0x4806e0 with proximity/visibility and population gates, restores
saved values/transform and clears an entry after successful creation. It also
captures eligible distant actors back into entries and marks their removal.

Destructor chain: actor 0x5feef0 -> 0x5fede0 removes both registration nodes;
0x6583e0 -> 0x658350 destroys dispatcher state, invalidates handle slot and calls
0x5611d0, which destroys children and unlinks object nodes. The frame queues
removal through 0x561370 and processes it in 0x561470; following exact delayed
queue rotation before describing final reclamation timing.
