# Texture sampling and mip policy

Slice 4 separates sampler state from texture construction. The original default
and the installed Steam configuration both create a single texture level.
Linear mip filtering is nevertheless part of the original sampler state; it
does not imply that a texture contains generated lower levels. Distant aliasing
alone therefore does not justify enabling a different texture policy.

## Original construction and configuration

The recovered two-dimensional constructor `0x41a6f0` and cube constructor
`0x41a420` pass `~(runtime_flags >> 7) & 1` as the D3D9 creation level count.
Zero requests the complete chain; one requests only level zero. Both constructors
first upload the decoded source surface. When additional levels exist, each
lower surface is loaded from the original full-size source with filter
`0x80005`, `D3DX_FILTER_BOX | D3DX_FILTER_DITHER`.

The configuration dialog `0x410750` maps saved setting bit 3 to runtime bit 7.
The default selected by `0x4102d0` is `0x2f1e52`, whose bit 3 is clear. The
runtime flag lives in the executable's zero-initialized tail. A read-only check
of the installed 36-byte `SystemSetting` file found `0x6f1e52` at offset 8;
its mip bit is also clear. This records the inspected configuration rather than
claiming every user's saved settings are identical.

The original optional path cannot be replaced faithfully by silently calling
Metal's recursive mip generator. Besides the source-per-level distinction, the
original requests dithering. Microsoft documents the
[filter flags](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dx-filter)
and [surface conversion operation](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dxloadsurfacefromsurface).
The optional path is now implemented and independently compared against the
original D3DX operation, including nonrecursive reductions, rounding and ordered
dithering. See [the filter contract and witnesses](texture-mip-filter.md) and
[launch-option ownership](lighting-texture-mip-generation.md). The default
remains off; sampler filtering does not implicitly enable generated storage.

Evidence is retained under `research/evidence/engine/pass-06l/`, `pass-06n/`,
`pass-06o/` and `pass-02b/`; relevant functions are the addresses above.
The source-resource interpretation remains in
[stage content decoding](stage-content-decoding.md).

## Sampler state and native boundary

Sampler initialization `0x451770` selects linear mip filtering for slots 0–11
and 15. Surface samplers wrap; the environment slot 7 clamps. The selected
stage pass changes surface minification to anisotropic filtering with maximum
anisotropy four, retaining linear magnification and mip filtering. The decoded
`SSSM LENV` override restores `MAXMIPLEVEL=0`, which permits the most detailed
level; it does not mean that the texture may only contain one level.

`WorldSurfaceState::mip_filter` now explicitly carries disabled, nearest or
linear filtering. An unresolved value rejects submission before replacing the
retained draw set. Metal translates the supplied surface policy and preserves
the independent linear environment policy. Changing only the sampler does not change texture allocation or byte
interpretation. Optional mip construction is separately selected at load time
and accounts for each retained level. Neither policy generates levels per
rendered frame; sampler objects retain the existing submission lifetime.

## Production reference and design decision

The reference is Unreal revision
`f45729c0b6f097038e72b52d366a62baeca3275b`,
`Engine/Source/Runtime/Apple/MetalRHI/Private/MetalTexture.cpp`:

- `FMetalTextureCreateDesc` explicitly transfers `NumMips` from the portable
  texture description into the Metal descriptor.
- `FMetalSurface::GetMemorySize` sums each resident mip and every cube face.

The inspected source snapshot is ignored research evidence. No Unreal code is
copied. The adopted boundary is explicit resource storage policy, separate from
sampling policy. The implemented optional original mip setting accounts for every resident
level and retains generated bytes/device ownership until consumers retire; it
does not infer allocation from the sampler. Default-off construction continues
to allocate only level zero. The linked mip implementation report supersedes
the earlier slice-4 decision to defer optional generation.

Header design and implementation each consulted both C++ MCP corpora and read
Core Guidelines `I.1` (`#ri-explicit`) and performance `GPU.9`
(`guidelines/gpu/GPU.9-suballocate-and-alias-transient-gpu-memory.md`). Their
application is explicit sampling inputs and setup-time retained state, with no
new per-frame allocation. The existing native scenario checks accepted sampler
policies and rejection of unresolved inputs; original-scene captures remain the
visual acceptance boundary, not a claim of improved texture resolution.
