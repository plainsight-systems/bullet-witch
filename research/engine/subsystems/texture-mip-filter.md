# Original texture mip filter

This is the portable numerical boundary of the optional texture chain described
in [texture mip ownership](lighting-texture-mip-generation.md). The portable
filter is implemented and numerically verified; native residency and launch-policy
validation are recorded in the ownership report.

The original `d3dx9_43.dll` shipped in the game's June 2010 redistributable was
extracted into ignored evidence and executed in an isolated x86 emulator.
Synthetic system-memory COM surfaces supply descriptions, locks and owned pixels;
heap, memory-copy and operating-system discovery imports are isolated stubs.
The filter and pixel-conversion instructions are unchanged. No DLL or extracted
source is added to Git. Initial probes used `D3DXLoadSurfaceFromMemory`; the final
corpus executes **`D3DXLoadSurfaceFromSurface` itself**, with both synthetic
source and destination COM surfaces. The original executable bytes are pinned by
SHA-256 `0b28546be22c71834501f7d7185ede5d79742457331c7ee09efc14490dd64f5f`.
The witness requests ordinary system-memory locking; unsupported external calls
fail instead of supplying guessed filter outputs.

Recovered behavior, independently exercised with synthetic impulses and colors:

- The original BOX selector has an exact-halving path, including truncated odd
  extents. It averages adjacent 2×2 samples (one sample on unit axes).
- Other reductions integrate the piecewise linear texel reconstruction over the
  destination footprint. Source coordinates wrap. This is not a simple average
  and is not recursive mip generation. For example, an 8-to-2 horizontal impulse
  at source zero contributes 0.21875 to output zero and 0.03125 to output one.
- Every lower level reads the original full base surface, independently per cube
  face. There are no cross-face taps, sRGB transforms or alpha premultiplication.
- UNORM quantization uses a 4×4 Bayer threshold with a serpentine scan: odd rows
  reverse the destination x index. This matters for widths not divisible by four.
  Dithering is active for eight-bit output too, not just reduced precision.
- HALF input uses the original finite exponent-31 convention, matching the
  existing shared math decoder. Output has **two distinct original algorithms**:
  paired pixels round halfway magnitudes toward zero and saturate at code
  `0x7c00`; an odd final pixel uses the scalar finite converter, rounds ties to
  even and retains values through `0x7fff`. The original pair instruction path
  (`101bc8fd`, dispatched by `101bc9b3`) normalizes subnormals with a float add,
  adds integer bias `0xc8000fff`, shifts by 13, then saturates. The scalar tail
  calls `1002fc9c`. This behavior is represented explicitly in shared math;
  normal IEEE HALF conversion would change both extended values and ties.
- Native UNORM readers multiply by the source precision's reciprocal. Four-bit
  input therefore uses the nibble multiplied by float `1/15`, rather than the
  expanded upload byte divided by 255. The difference affects exact thresholds.
- Exact BOX accumulation preserves all-negative signed zeros; the general
  integrated-filter accumulator starts at positive zero, matching the original.

The public representation retains four-bit staging precision through an explicit
`rgba4` format whose upload bytes are expanded nibbles. Native targets upload the
expanded bytes; filtering re-quantizes each lower level to the original precision.
The independent base conversion helper uses nearest quantization without dither.
The original `NONE` initial conversion copies a smaller source into the top-left
of the even-sized destination and explicitly writes zero RGBA to the added right
column/bottom row. Prefilling the destination with `0xAB` distinguishes that
behavior from uninitialized storage. The decoder owns this padding; the mip
filter consumes the resulting complete staging surface.

## Reference comparison

[Wine's D3DX helper implementation](https://github.com/wine-mirror/wine/blob/e3c3d348676128bc745c40aa6397b51951ef1cd6/dlls/d3dx9_36/d3dx_helpers.c)
was inspected at the pinned revision shown in the URL, especially
`box_filter_argb_pixels` and `d3dx_load_pixels_from_pixels`. It identifies BOX's
fallback to other filter classes, but does not implement this complete triangle
and dither path. Its native expected-data tests are useful corroboration; its
implementation is not imported. The original DLL supplies stronger evidence.
Microsoft's [filter flags](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dx-filter)
describe `0x80005` as BOX plus ordered dithering; no mirror or sRGB flags are set.
The pinned Unreal comparison in the ownership report remains applicable to
resource ownership, but its recursive GPU algorithm is not the source filter.

## Contracts and cost

The base is borrowed immutably. Generated bytes, coefficient tables and separable
scratch storage use the caller's memory domain. Output is level-major and each
cube level contains six complete faces. Exact byte sizes and finite dimensions
are checked before publication. No settings access, native handles, lazy upload
or runtime mutation lives in this numerical module.

Both design and implementation retrieved Core `SL.con.3` (checked bounds) and
Performance `MEM.6` (injected allocation). Header design additionally retrieved
Core `I.1`. The result preserves the source CPU load-time filtering boundary;
this is not a claim that it is the preferred future optimization strategy.

## Numerical acceptance

The final standalone C++ executable links the actual portable generator. Its
output is compared against untouched original DLL filtering of the same
synthetic bases. The harness requires exactly one result record for each input
and an exact byte length before comparing contents; truncated output cannot
silently shorten the comparison.

- **189 base cases, 517 generated face-levels:** RGBA8, finite HALF and RGBA4;
  square, rectangular, one-dimensional, odd, non-power-of-two and cube layouts;
  seeded colors, subnormals, signed zeros and exponent-31 values.
- **98,632 components identical**, comprising 74,380 preserved base components
  and **24,252 generated components**. Zero tolerance, zero differing cases.
- Initial `NONE` conversion separately checked all 256 input byte values into
  four-bit staging, and 3×3→4×4, 3×2→4×2, 2×3→2×4 padding with a nonzero
  destination sentinel. All comparisons exact.
- Public unit contracts cover full-base independence and wrapping, serpentine
  Bayer phase, both HALF packing policies, four-bit precision, cube face order,
  invalid staging rejection, immutable base ownership and domain-budget rollback.
  These are part of the existing `image-font` suite, which passes.
- Scoped fatal clang-tidy passed for `texture_mips.cpp` and
  `texture_mips_test.cpp`, including the changed math header. Full repository
  gates and native upload acceptance are coordinated by the owning integration
  task, not inferred from this portable test result.

Reproduction artifacts are ignored under
`research/evidence/reconstruction/texture-mip-filter/`: original DLL, synthetic
COM harness, retained instruction trace, standalone C++ consumer, deterministic
case inputs/expected outputs, strict comparison summary and SHA-256 manifest.
The authored implementation and this report contain no copied DLL code. The
witness establishes the tested original CPU path; it does not assert every
historical D3DX CPU-dispatch variant has identical rounding or that this load-time
CPU algorithm is preferable for a later graphics upgrade.
